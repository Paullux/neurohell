# CI/CD — Build automatisé

**Workflow** : `.github/workflows/godot-build.yml`
**Branche** : `game`

---

## Déclenchement

| Événement | Condition | Résultat |
|---|---|---|
| Push de tag | `v[0-9]+.[0-9]+.[0-9]+` | Build + Release GitHub |
| `workflow_dispatch` | Manuel depuis GitHub Actions | Build + Release avec version choisie |

Les pushs sur la branche `game` sans tag **ne déclenchent pas** le CI.

---

## Pipeline

### 1. Export (matrice parallèle)

Deux jobs tournent en parallèle sur `ubuntu-22.04` :

| Job | Preset Godot | Fichier produit | Archive |
|---|---|---|---|
| Windows | `Windows Desktop` | `NeuroHell.exe` | `NeuroHell-Windows.zip` |
| Linux | `Linux` | `NeuroHell.x86_64` | `NeuroHell-Linux.zip` |

### 2. Étapes de chaque job

```
1. Checkout (avec LFS)
2. Cache LFS objects (actions/cache@v4, clé basée sur .gitattributes + SHA)
3. git lfs pull
4. Installer Godot 4.6.2 headless + templates d'export
5. Écrire scripts/game_version.gd (VERSION + BUILD_DATE)
6. Import des assets (timeout 900s)
7. Export release (godot --headless --export-release)
8. Zipper le build
9. Upload artifact (retention 14 jours)
```

### 3. Release GitHub

Job `release` dépend des deux exports. Utilise `softprops/action-gh-release@v2` pour créer une release avec les deux archives attachées.

## Version automatique (`game_version.gd`)

Le CI écrit ce fichier avant chaque export :

```gdscript
# AUTO-GENERATED BY CI — NE PAS ÉDITER MANUELLEMENT
class_name GameVersion
const VERSION    := "v1.2.3"    # tag git
const BUILD_DATE := "2026-05-03"
```

En développement local, le fichier contient `"dev"` et `"2025-01-01"`.
Le menu principal et l'écran de téléchargement in-game utilisent ces constantes.

## Point critique : répertoire des templates

Godot 4 cherche les templates dans :
```
~/.local/share/godot/export_templates/4.6.2.stable/
```

Attention au **point** (`4.6.2.stable`) et non au tiret (`4.6.2-stable`).
Le YAML utilise :
```yaml
TPL_VERSION="${GODOT_VERSION}.${GODOT_STABILITY}"
```

## Cache LFS

Le cache `actions/cache@v4` est configuré avant `git lfs pull` :

```yaml
key: lfs-${{ hashFiles('.gitattributes') }}-${{ github.sha }}
restore-keys: |
  lfs-${{ hashFiles('.gitattributes') }}-
  lfs-
```

- Cache hit → pas de téléchargement LFS réseau
- Cache miss (nouveau SHA) → pull LFS + mise en cache pour le prochain run

---

## Quota LFS GitHub

- **Gratuit** : 10 Go/mois de bande passante
- **Dépassement** : facturation à ~$1.63/Go (couvert par les crédits inclus)
- **Stratégie** : builds uniquement sur tag, cache LFS activé → un seul `git lfs pull` complet par cycle de releases

## In-game update checker (`update_checker.gd`)

Autoload qui vérifie silencieusement au démarrage (délai 3s) :
```
GET https://api.github.com/repos/Paullux/neurohell/releases/latest
```

Si `latest.tag_name != GameVersion.VERSION` → affiche un panneau de notification cyberpunk (CanvasLayer layer 5, auto-dismiss après 12s).
